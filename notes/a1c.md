## 1. What compile-time evaluation is, in two halves

`src/nimony/semconst.nim` has no "in-process or sub-compile" branch of its own —
it is a thin layer over `expreval.evalExpr`/`eval` that only validates the
*shape* of whatever came back (`isConstBoolValue` &c.). The decision is inside
`expreval`.

### 1a. `src/nimony/expreval.nim` — folded in-process

Literals (`StrLit CharLit IntLit UIntLit FloatLit`); `TrueX FalseX NanX InfX
NeginfX NilX`; `AndX OrX NotX` (short-circuit, bool operands required); `SufX`;
`ConvX HconvX` (targets restricted to `{Float, UInt, Int, Char, Enum}`; a
distinct conversion strips to the underlying value unconditionally); `CastX` via
`evalCast` (float↔int bit-cast, ordinal↔ordinal, `nil`, `cast[ptr U](addr X)`
kept verbatim); `DconvX`; `ExprX` when the leading statements are all empty;
arithmetic `NegX MulX AddX SubX DivX ModX BitorX BitandX BitxorX BitnotX ShlX
ShrX AshrX`; comparisons `EqX LeX LtX`; `IsmainmoduleX`; the constructors
`AconstrX SetconstrX TupconstrX BracketX CurlyX TupX OconstrX`; `AddrX`;
`SizeofX` (through `c.c.semGetSize`, so it needs a live `SemContext`); the set
ops `PlussetX MinussetX XorsetX MulsetX`, `InsetX`, `CardX`.

`evalCall` folds only a whitelist keyed on the callee's `.semantics:` pragma:
`"string.&"`, `"string.=="`, `"string.len"`, `"slurp"` (reads the file itself,
relative to the *source* file), and `"newSeqUninit"` **only when the size
argument is the literal 0** (the empty `@[]`). Everything else is forwarded to
`executeExpr`.

### 1b. `src/nimony/exprexec.nim` — the sub-compile

`executeExpr` (line 728) synthesises a whole program: it re-emits every symbol
the expression touches (`collectUsedSymsFromExpr`), imports `std/writenif`,
wraps the body in `try/except` so `.raises` callees sem-check, appends a
serializer generated by `entryPoint`/`unravel`, then `rewriteSymsToIdents` +
`semos.runEval`.

`semos.runEval` (line 752) writes `<nifcache>/<srcName>.p.nif` and
`<nifcache>/<srcName>.p.deps.nif`, compiles and runs that program with
`nimony s`, and parses the result back from **`<nifcache>/<srcName>.out.nif`** —
confirmed at `semos.nim:774`. `srcName` is `c.newModuleSuffix`,
`thisModuleSuffix.substr(0,2) & computeChecksum(mangle(expr, ...))`, so there is
one `.p.nif`/`.out.nif` pair per distinct expression. Plugin outputs land on the
same `*.out.nif` name shape (`semos.nim:658`), which is why `ctfediff` collects
by glob rather than by a single name.

Modes: nimony has **no `--vfs` flag today** (A1b adds it). A1c therefore runs
disk vs disk, and the mode strings stay CLI-flag strings so B2 can pass
`--ctfe:subprocess` vs `--ctfe:engine` unchanged.

## 2. Result-type matrix, as measured

`unravel`'s dispatch (`exprexec.nim:593`) says what is *intended* to work. What
actually works was measured by writing the test and running it; the two disagree
in four places.

| result type | dispatch says | measured |
|---|---|---|
| int / uint / float / bool / char | `entryPoint` → `writeNifInt/UInt/Float/Bool/Char` | works |
| string | `isSomeStringType` short-circuit → `writeNifStr` | works |
| object, nested object | `unravelObj` (recurses; inheritance, case objects, private fields) | works |
| tuple, incl. named/mixed | `unravelTuple` | works |
| array, incl. `array[N, string]` | `unravelArray` | works |
| `seq[int]`, `seq[string]` | ObjectT + `unravelPtrUarrayField` | works |
| `Table[string,int]`, `Table[int,string]` | same | works |
| `seq[UserObject]` | same | **fails**: `undeclared identifier: <T>` in the sub-compile |
| enum (`EnumT/OnumT/AnumT`) | `unravelEnum` | **crashes**: `nifcore.nim(895,3) c.rem == 0` |
| `set[T]` | `unravelSet` | **crashes**: `exprexec.nim(413,13) not err` |
| distinct, range | `entryPoint` `(conv …)` wrapper | **fails**: no conversion on the argument |
| cstring | `entryPoint` special case only | untested |
| ref, ptr, proc/closure, typedesc, concept, … | explicit unsupported bucket | fails cleanly, with a proper diagnostic |

The four failures are written up per case in
`tests/nimony/consteval/todo/README.md`, each with the finished test file.

`sizeof` is folded in-process, so a `sizeof`-dependent value is a *mixed* case:
the size is substituted before the sub-compile is synthesised and the
sub-compile computes with it (`tconstsizeof.nim`).

## 3. Failure-mode diagnostics

The one failure mode that reaches the user properly is an unsupported result
type: `cannot evaluate expression at compile time: <expr>` followed by
`unsupported type for compile-time evaluation: <type>`. That is
`tconstunsupported.nim` + `.msgs`.

An evaluation that *raises*, and one that reads a missing file, both end as

```
[Error] cannot open: nimcache/tco<sha1>.out.nif
```

— no source location, no cause. Beyond being a bad message this cannot even be
recorded as a `.msgs` golden of the bad behaviour: `runner.nim:82` infers the
expected compiler exit code as `if msgSpec.contains(ErrorKeyword): 1 else: 0`
with `ErrorKeyword = "Error:"` (`context.nim:21`), and `[Error]` is not
`Error:`, so hastur expects 0 while nimony exits 1. Verified with a byte-exact
golden in place. Both tests are in `todo/`.

## 4. How hastur treats the directories this phase adds

- `walk.collectTests`: a directory with `.nim` files of its own is a **leaf** and
  its subdirectories are *not* descended into. So `consteval/todo/` is inert,
  exactly like the existing `consteval/doc/` fixture directory. The one trap: if
  a leaf's subdirectory contains a `setup.nim` or a `hastur.mode`, the walk quits
  with a hard failure ("groups test suites … but also holds test files").
  `todo/` therefore holds neither, and its README says so.
- `.output` is compared stripped; a test with no `.output` is expected to print
  nothing (that is why `tconstseq.nim` and `tconsttable.nim` have none).
- `.msgs` disqualifies a test from the joined group (`joined.joinable`), so
  `tconstunsupported.nim` gets its own process — which is what a compile-error
  test needs.
- `setup.nim` owns its directory: hastur runs
  `nim c -r --nimcache:<cache>/setupnim/<dir> -o:… <dir>/setup.nim -- --dir:…
  --bindir:<toolchainDir> --cachedir:<nimcacheDir> [--overwrite] [--forward:…]`
  and takes the exit code as the verdict; it does not read stdout. Every runner
  parses those with its own three-line `arg()` helper.
- A `setup.nim` imports `src/hastur/kit` and nothing else from `src/hastur`, so
  `ctfediff` has to be added to `kit.nim`'s import/export lists. No entry in
  `hastur.nim`'s command dispatch is needed — `setup.nim` files are found by
  `fileExists`, and `build all` never compiles them (they are compiled on
  demand, per run).
- Toolchain resolution is `context.toolchainDir` (hastur's own directory, else
  `bin`, else `$PATH`), overridable with `--bindir`; `nimcacheDir` defaults to
  the relative `nimcache`.
