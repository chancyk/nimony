## 1. The seam, as it is today

`expreval` folds what it can in-process and hands everything else to
`SemContext.executeExpr` (`src/nimony/exprexec.nim:728`). That proc synthesizes a
whole PROGRAM — `import std/writenif`, the caller's imports, a
`setup("<abs>/<sfx>.out.nif")` call, the expression wrapped in the tested
`entryPoint`/`unravel*` serializer, `teardown()` — and its LAST statement is

```nim
result = runEval(s, dest, c.newModuleSuffix, c.dest, c.usedModules, sourceDir)
```

`<sfx>` is `thisModuleSuffix[0..2] & computeChecksum(mangle(expr, …))`: the same
expression always names the same file, which is what makes the memo sound.

`semos.runEval` (`src/nimony/semos.nim:940`) is therefore the only place the
engine has to exist. It:

1. `writeEvalProgram` → `<nimcache>/<sfx>.p.nif` (only if the bytes changed),
2. `writeEvalImports` → `<sfx>.p.deps.nif`,
3. `if not evalMemoIsFresh(c, m)`: `runProgram` — which spawns
   `nimony <forwarded args> --nimcache:<dir> s <sfx>.p.nif` and then RUNS
   `<nimcache>/<sfx>/<sfx>.p`,
4. re-reads `<sfx>.out.nif.reads` and `recordFileDep`s each line,
5. parses `<sfx>.out.nif` straight into `dest`.

Steps 1, 2, 4 and 5 are mode-independent. **Only step 3 changes.**

`std/writenif` gets its output path as a compiled-in string literal, opens it
with `std/syncio`, and writes the `.reads` sidecar LAST — its presence is what
`evalMemoIsFresh` reads as "this run completed". So an engine that lets the
guest do its own file I/O needs no changes anywhere else in the memo.

## 2. What the sub-program is, at run time

Measured on this host (`nm -u` on a linked `<sfx>.p`, `otool -L`):

```
__exit  __tlv_bootstrap  _bzero  _close  _dlopen  _dlsym  _getpid  _kill
_memcpy  _mmap  _open  _strlen  _write
```

`otool -L`: `/usr/lib/libSystem.B.dylib` only. Thirteen names, all
integer/pointer-only, and the important thing is what is NOT there: no `malloc`,
no `fopen`/`fwrite`, no pthreads. `nimony.nim`'s `compileProgram` turns on
`nimNativeAlloc` and `nimNativeIo` for **every** backend unless `-d:useLibc`, so
the guest already runs its own `mmap`-backed region allocator and raw-syscall
I/O. JIT.md 7.2 assumed this; it is true today.

Three consequences for the engine:

* **`kill` must be intercepted.** `cAbort` (`lib/std/system/exits.nim`) does
  `kill(getpid(), SIGABRT)` before `_exit(127)`. In-process, `getpid()` is
  nimsem's pid, so an out-of-memory guest would SIGABRT **the compiler**. This
  is the one interception that is not optional.
* **`write` is the whole of the guest's diagnostics.** `panic`/`raiseIndexError`
  go through `cWriteErr` → raw `write(2, …)`. Intercepting `write` (fd 1 and 2
  into a buffer, everything else straight through to the real syscall) captures
  exactly what `execCmdEx` captures on the subprocess path, and lets the guest's
  own `.out.nif` writes reach the disk unchanged.
* **`main` returns; it does not `exit`.** `hexer/lengcgen.nim`'s `genMainProc`
  calls `cExit(0)` only on the native backend; on the C backend it ends in
  `nimFlushStdStreams(); return 0`. The C-backend `.c.nif` is what B1
  demonstrated against, so the ordinary outcome is `goReturned` with status 0
  and no parked thread.

`__tlv_bootstrap` is the C compiler's doing, not hexer's: `localErr`, `exc` and
the allocator's `MemRegion` are `{.threadvar.}`. nifasm's `--dev-single-thread`
lowers every `(tvar …)` to a plain global, and `layInMemory` REFUSES an image
that still has thread-locals — so the flag is mandatory and cannot be forgotten
silently.

## 3. Where the `.c.nif` files come from

P0b split the backend of a `.p.nif` project into two nifmake graphs
(`deps.nim:2349`):

```nim
let useObjectCache = project.endsWith(".p.nif") and
                     c.config.backend == backendC and
                     c.config.optLevel notin {optSpeed, optSize} and
                     c.backendTools.len == 0 and c.bundles.len == 0
```

* `fpAnalysis` → `<sfx>.final1.build.nif`: nifler, nimsem, hexer, `dceLive`,
  `dceEmit`. It stops before `lengc`, so when it returns **every module's
  `.c.nif` exists** and no C compiler has run.
* `fpCodegen` → `<sfx>.final2.build.nif`: `lengc`, `cc`, `link`.

`backendDirName` is the bare module suffix for the C backend, so the files are
`<nimcache>/<sfx>/<modsuffix>.c.nif` — main module and its whole closure in one
directory. That is exactly the set B1 fed to arkham. The engine therefore needs
only the FIRST graph, and the smallest possible change to `buildGraph` is a
`return` right after `fillObjectCache`, inside the `if useObjectCache` block
that already restricts this path to CTFE sub-programs. It is far above the
`Stats` block (A1d's), which the early return skips — correct, since nothing was
built to report on.

## 4. The nativenif API (branch `jit/b1`, head `e368478`)

arkham (`src/arkham/generate.nim`):

```nim
proc generateAsmBuf*(buf: var TokenBuf; target: AsmTarget; inputPath: string;
                     tags: TagPool; board = layout.Layout()): AsmModule
```

`AsmTarget` for macOS/arm64 is `atA64`. `tags` is arkham's LENG tag pool
(`createLengTagPool()`, `arkham/core/lengdecl.nim`), shared with the
`parseFromFile` that produced `buf`. It is NOT `asmTags` — that is nifasm's
seeded asm pool, a process-wide `let` in `nifasm/core/tagpool.nim` that
`initAsmBuf` hard-codes, so an embedder never constructs it.

nifasm (`src/nifasm/driver.nim`), in the order the state machine requires:

```nim
openSession(mainPool, baseDir, thisModule, …, singleThread = true)
addMainModule(s, buf)          # exactly once
addModule(s, name, buf)        # every foreign module, BEFORE declare()
declare(s); beginEmit(s); emitTopLevel(s); emitRoots(s); finishCode(s)
# NO synthesizeProcessEntry: a loaded image is not a process
```

then `hostrun.nim`: `reserveArena()` → `loadImage(s.ctx, arena)` (wraps
`image/memory.layInMemory`) → `bindExternals(img, host)` → `makeExecutable` →
`runImage`. `defaultHostSymbols()` already intercepts `exit`/`_exit` with
`guestExit`, which parks the guest thread and wakes the host.

`declare()` snapshots `s.ctx.modules.keys` at call time, so a module registered
after it is never `pass1`'d. `addModule` had **no caller** on `jit/b1` —
`nifrun` and `memimage_selftest` both feed one main module and let the rest be
opened lazily from disk. B2 is its first caller and brings the test.

`AsmError` (`core/asmerror.nim`) is the refusal channel; `AssertionDefect` and
friends deliberately are not — they say the assembler has a bug.

### Two things `jit/b1` did not have, added here

1. **Nimony's `src/lib` was reachable only by a hard relative path.** Six
   imports named `"../../../nimony/src/lib" / …`, which is the sibling of the
   nativenif checkout — i.e. the MAIN nimony working tree, never a linked one.
   Compiling nimsem out of a `git worktree` therefore put two copies of
   `nifreader`, `symparser` and friends into one program, and nothing
   type-checked across the seam (`nifreader.close(module.foreign.r)` reports a
   type mismatch between two types both spelled `Reader`). Fixed in nativenif
   `015dcbb` by naming them `lib / nifreader` and `models / [leng_tags, tags]`
   and putting `.../nimony/src` on each `nim.cfg`'s search path. Refactor gate:
   2583 artifacts, 774 listings, byte-identical.
2. **`runImage` had no deadline.** `pthread_cond_wait`, no timeout hook. Fixed
   in nativenif `3d20d5c`: `runImage(…, budgetMs = 0)`, `pthread_cond_timedwait`
   and a new `goTimedOut`. A timeout leaves the guest thread running and leaves
   `gGuest.running` SET on purpose, so the process runs no further guest — a
   foreign frame cannot be stopped from outside.

`runImage` was ALREADY safe to call repeatedly: `gGuest` is fully repopulated
per call and `running` is cleared at the end. Only a guest that actually calls
`exit` costs a parked thread, and the CTFE guest's `main` returns.

## 5. The other coupling: `nimPreviewSlimSystem`

`src/config.nims` sets `--define:nimPreviewSlimSystem` for everything under
`src/`, and nativenif does not: 27 of its modules use `assert` without importing
`std/assertions`. A nimsem that links them has to undefine it. That is a
property of the ENGINE build only (`-d:nimonyEngine`), and `hastur boot` is what
proves it changed nothing nimsem does.

## 6. The four parked CTFE bugs (`tests/nimony/consteval/todo/README.md`)

Reproduced on this host. Three of the four never reach `runEval` at all, so the
engine cannot change them:

| test | fails in | how |
|---|---|---|
| `tconstenum` | nimsem | `AssertionDefect` in `unravelEnum` — "body did not consume all 14 children" |
| `tconstsetres` | nimsem | `AssertionDefect` at `exprexec.nim:413`, `not err` |
| `tconstdistinct` | nimsem | ordinary type-mismatch diagnostics, sub-program never built |
| `tconstseqobj` | nimsem | `undeclared identifier: Point`, then `got: Point but wanted: Point` |
| `tconstraise` / `tconstmissingfile` | the GUEST runs and exits 0 | the catch-all `except` swallows the failure, `.out.nif` is 0 bytes, and the compiler reports only `[Error] cannot open: …out.nif` |

Only the last pair exercises the engine, and it must reproduce it: run to
completion, status 0, an empty `.out.nif`, and the same "cannot open"
diagnostic from `rd.open`.

## 7. Plan

* `--ctfe:subprocess|engine` in `cli.nim` — `parseCommonOption` is shared by
  nimony and nimsem, and `forwardArg` stays true, so the flag rides
  `c.commandLineArgs` to every sub-compile with no other plumbing. Default
  `subprocess` until the gate says otherwise.
* `src/nimony/engine.nim`, all of it under `when defined(nimonyEngine)`: the
  `.c.nif` set → `generateAsmBuf` per module → one `AsmSession` → arena → run.
  `EngineResult` carries an outcome, the captured output and per-stage timings.
* `runEval`: on `--ctfe:engine`, run the sub-program's frontend + analysis
  graphs only, then the engine; anything the engine refuses falls back to the
  full subprocess path (JIT.md 7.5) except a budget overrun, which is a
  diagnostic — re-running something that loops forever is not a recovery.
* Per-proc code cache and the `emitRoots` stdlib closure stay out of this phase.
