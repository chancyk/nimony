== the pair the phase is judged on ==========================================

| scenario                     | `nimony n -r` | `nimony r` | ratio |
|------------------------------|---------------|------------|-------|
| hello, one-line edit  (wall)  | 0.320 s       | 0.033 s    | 9.7x  |
| hello, one-line edit  (cpu)   | 0.046 s       | 0.030 s    | 1.5x  |
| compiler, sem.nim body (wall) | 2.044 s       | 1.929 s    | 1.06x |
| compiler, sem.nim body (cpu)  | 1.902 s       | 1.976 s    | 0.96x |

`self.editbody` -- the same edit with no run at all, just `nimony n` writing
the executable -- is 1.911 s.  So on the compiler:

    self.run (1.929) ~= self.editbody (1.911) + 0.018

which is what was predicted before measuring: `nimony r` is the build plus the
whole-image assemble, and the assemble did not get cheaper by moving into the
compiler's address space -- it only stopped being followed by a Mach-O write,
an ad-hoc code signature and an exec.  Those three are the 0.115 s between
`self.nrun` and `self.run`, and they are a fixed cost, which is why the same
three are 0.287 s of hello's 0.320 s: for a tiny program the exec IS the
scenario.

The number that matters for the dev loop is therefore still 1.07 s of assemble
per run, and it is B3's, not B1's.  B1 removed everything around it.

cpu-sum reads the other way on the compiler (1.976 vs 1.902) because the
assemble now runs on the compiler's own thread and is counted, where nifasm's
was a child whose cpu the harness also sums -- the two are the same work; the
0.07 s is the process nifasm no longer is, minus the arena mapping.

    the same assemble in-process, into an arena          1.077 s  (assemble+lay+bind)

37 external symbols, all resolved by `dlsym` against the compiler's own libc;
no arkham runs beyond the 3 the graph did (the engine runs none: arkham stays
in the build graph, see notes/b1-nimony.md §4).

hello (4 modules, 21 KB of code), same treatment:

    nimony r      arkham 0.005 s (1), hexer 0.001 s, dceEmit 0.000 s
                  [run-engine] b1nyj6fzm assemble=7.03ms lay=0.08ms bind=0.02ms

    nimony n -r   link 0.018 s, arkham 0.004 s, hexer 0.001 s, dceEmit 0.000 s

== a bug in the benchmark script, fixed here ================================

`devloop_bench.sh <root>` kept `root` as given, and the `self.*` scenarios run
their command under `cd` into a scratch copy of the sources.  With the `.` that
JIT_IMPL.md's measurement protocol spells, `./bin/nimony` then resolved against
the wrong directory and every `self.*` row was the 5 ms of a failing `sh -c`:

    self.cold       wall   0.006  cpu   0.004
    self.editbody   wall   0.005  cpu   0.004
    ...
    (stderr: sh: ./bin/nimony: No such file or directory, x21)

`root` is absolutised now.  Any earlier table whose `self.*` rows are single-
digit milliseconds was measuring nothing.
